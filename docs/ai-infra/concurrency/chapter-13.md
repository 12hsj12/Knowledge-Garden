# 并发基础：第 13 章 编写并发应用

前面各章建立了并发程序的工具箱：任务分解、进程和线程、通信、同步、网络 I/O、事件循环与协程。本章把这些知识放回应用设计中，介绍 Foster 的并行程序设计方法，并用矩阵乘法和分布式词频统计说明怎样从问题推导出并发方案。

主线是：**Partitioning → Communication → Agglomeration → Mapping → Implementation**，即**划分、通信、聚合、映射与实现**。

## 1. 从问题结构开始，而不是先开线程

设计并发程序时先理解问题：输入和输出是什么？哪些子任务独立？哪些任务需要彼此的数据？任务应该放在哪些执行资源上？最后如何判断实现是否变快、结果是否正确？

找到可以并发的工作后，再选择线程、进程、事件循环、GPU 线程或分布式 Worker。工具服务于依赖结构和资源约束。

## 2. Foster 方法：四个设计步骤

### 2.1 Partitioning：划分问题

**划分（partitioning）**把原问题拆成多个子任务，暴露足够的并发工作，并让任务边界清楚。

- **数据划分**：把输入分块，每块运行相同计算，例如多个文件分别统计词频。
- **功能划分**：把流程拆成不同阶段，例如读取、解析、转换与写入。

要检查子任务是否独立、数据量是否均衡、分区是否过多或过少。分区过少会限制并行度，过多会增加调度和通信成本。

### 2.2 Communication：分析通信与依赖

**通信（communication）**说明子任务要交换哪些数据、何时交换、由谁汇总。通信成本包括复制、序列化、网络传输和同步等待。

数据可以通过共享内存、线程安全队列、进程间通信、Socket 或分布式消息传递。即使计算可并行，若通信和协调成本超过计算收益，增加并行度也可能变慢。

### 2.3 Agglomeration：合并小任务

**聚合（agglomeration）**把相关的小任务合成较大的工作单元，减少调度、通信和同步开销。

例如把许多小文本块组合后交给 Worker，或先在本地合并部分结果再发送。聚合太少会带来大量小任务开销；聚合过度则会减少并行度、造成负载不均。目标是在并行度和管理成本间找到合适粒度。

### 2.4 Mapping：分配到执行资源

**映射（mapping）**把任务分配到处理器、线程、进程、GPU 或机器。设计时考虑：

- **负载均衡**：让各执行资源工作量接近，减少拖尾；
- **数据局部性**：尽量让任务靠近其所需数据，减少传输；
- **通信拓扑**：频繁交换数据的任务尽量放在通信成本低的位置；
- **资源与故障**：Worker 速度可能不同，也可能失效，需要重试或重新分配。

静态映射简单但不适应变化；动态调度按完成情况继续派工，更灵活，也需要额外调度状态和通信。

## 3. 案例一：矩阵乘法

矩阵 C = A × B 的每个输出元素由 A 的一行和 B 的一列计算得到：

~~~text
C[i,j] = 对所有 k 求和 A[i,k] * B[k,j]
~~~

**划分**：将输出矩阵的行、列或二维 Tile 分给不同工作单元。各任务写入互不重叠的输出区域，便于并行。

**通信**：任务需读取 A、B 的对应数据。若任务跨节点运行，输入块还要传到相应节点。

**聚合**：逐个输出元素建任务过细。把相邻元素组合成 Tile，可以复用同一批输入数据并减少任务数量。GPU 的 Tiling 和 Shared Memory 复用也体现这一思路。

**映射与实现**：将 Tile 分配到 CPU Worker、GPU Block 或节点上；处理矩阵边界、数据布局、同步和结果收集。最后测量计算、搬运、调度与通信各自的成本。

## 4. 案例二：分布式词频统计

统计大型文本集合中每个单词出现的次数。文本可以分区独立处理，但相同单词可能出现在不同分区，因此最后需要按词汇总。

~~~text
文件/文本块
→ 多个 Worker 计算局部词频 Map
→ 按单词发送和分组（Shuffle）
→ 合并同一单词的计数 Reduce
→ 输出全局结果
~~~

**划分**：多个 Worker 分别处理不同文件或文本块，生成局部词频。

**通信**：相同单词的局部计数要发送到同一聚合位置，才能合成全局结果。按键重新分组产生 Shuffle 通信。

**聚合**：可以把小文本块组合后再派发；Worker 也可先在本地合并词频，以局部总数代替每次单词出现记录，减少网络传输。

**映射**：文本分区分配给 Worker，单词映射到聚合 Worker。需关注数据倾斜；少数常见词可能让某个聚合者成为热点。

**实现**：处理文件边界、编码、分词规则、Worker 失败重试、重复提交去重和结果仅汇总一次等问题。

这展示了 MapReduce 的结构：Map 在分区内生成中间键值对，Shuffle 按键分组，Reduce 合并同键数据。它适合能分区计算、按键聚合的数据任务。

## 5. 设计检查表

| 步骤 | 要回答的问题 | 产物 |
|---|---|---|
| Partitioning 划分 | 工作如何分成独立部分？依赖在哪里？ | 任务图、数据分区 |
| Communication 通信 | 交换什么数据，何时交换？ | 消息、队列、共享状态和同步边界 |
| Agglomeration 聚合 | 哪些小任务应合并？ | 任务粒度、批次大小 |
| Mapping 映射 | 任务分配给哪些执行资源？ | Worker、线程、设备和节点映射 |
| Implementation 实现 | 如何运行、处理错误并合并结果？ | 程序、监控与性能测量 |

方法是可迭代的：网络成本太高时改变划分或做本地聚合；负载不均时调整映射和粒度；共享状态争用严重时改造数据所有权和通信方式。

## 6. 单机并发与分布式并发

单机线程共享地址空间，数据传递直接，但需要处理数据竞争和锁。多进程隔离性更强，进程间需要 IPC。分布式节点通过网络通信，还要面对延迟、序列化、超时、重复消息与机器故障。

增加机器不是简单增加 Worker 数量，还要解决数据分区与传输、慢节点、重试、持久化、背压和结果一致性。并行可以增加同时执行的工作量；分布式还引入跨机器协调与容错成本。

## 7. 全书主线：从硬件到应用设计

全书可以按四层回忆：

1. **并发基础**：并发与并行、处理器、硬件层次和任务独立性。
2. **执行与分解**：进程、线程、多任务调度、IPC、Pipeline、Map、Fork/Join 与 MapReduce。
3. **正确性与进度**：共享状态、竞态、锁和信号量、死锁、活锁与饥饿。
4. **I/O 与应用设计**：Socket、阻塞/非阻塞 I/O、事件循环、协程和 Future，再用划分—通信—聚合—映射设计完整应用。

面对工程问题，可以沿着这条线问：工作能否独立？瓶颈是计算还是等待？数据怎样传递？共享状态如何保护？任务怎样分配与限流？错误、超时、重试和不均衡怎样处理？最后用测量确认设计效果。

## 8. 本章小结

- 并发应用设计从问题结构和依赖开始，而不是从创建线程开始。
- Foster 方法通过划分、通信、聚合和映射组织并行程序设计，并用实现与测量反复验证。
- 矩阵乘法可按输出 Tile 划分；数据复用和任务粒度影响通信与计算效率。
- 分布式词频统计需要局部 Map、按键 Shuffle 和全局 Reduce；本地聚合能减少网络流量。
- 分布式计算扩大资源规模，也增加网络通信、故障恢复、数据倾斜与一致性成本。
- 全书从硬件和任务执行逐步推进到同步、网络 I/O、事件循环、协程与应用设计。

### 面试表达：怎样设计可扩展的并发数据处理程序？

> 我会先分析依赖关系，将输入划分成可独立处理的任务，再定义任务之间需要交换的数据和同步边界。接着结合调度与通信成本确定任务粒度，避免任务过碎；再依据数据局部性和执行资源能力进行映射，控制负载倾斜。实现阶段处理失败重试、幂等、背压与结果汇总，最后分别测量计算、调度和通信成本，并根据瓶颈调整方案。
