# 并发基础：第 4 章 并发程序的基本构件

第 1 章介绍了并发的价值，第 2 章区分串行、并发与并行，第 3 章说明了运行时和硬件怎样协作。本章继续回答一个实际问题：程序要怎样把多项工作交给操作系统和硬件执行？

并发程序通常先把应用拆成可以独立推进的任务，再用进程或线程承载这些任务。操作系统负责管理执行上下文并把可运行的线程安排到处理器上。进程提供资源和隔离边界，线程提供具体的执行路径。[本章目录与学习目标](https://livebook.manning.com/book/grokking-concurrency/chapter-4)

## 1. 并发程序的设计步骤

设计并发程序时，可以沿着“问题 → 任务 → 执行单元 → 协调 → 性能”这条线思考：

1. **明确要完成的工作**：输入是什么、需要得到什么结果，先建立可验证的整体逻辑。
2. **拆分任务并找出依赖**：哪些步骤能独立推进，哪些必须等待另一个步骤的结果。
3. **检查共享数据与隔离要求**：任务需要共享哪些状态？一个任务出错时，是否应该影响其他任务？
4. **选择执行抽象**：根据共享程度、隔离要求和工作负载，选择进程、线程或更高层的任务机制。
5. **设计通信和协调**：决定结果如何汇总，如何管理共享状态，何时等待任务完成。
6. **映射到运行时和硬件**：操作系统调度线程，处理器核心执行它们；可用核心和任务依赖决定是否能真正并行。
7. **检查正确性与性能**：验证结果、异常和资源清理，再用延迟、吞吐、CPU 使用率和内存占用评估效果。

增加进程或线程只是建立多个执行单元。任务是否真的并行，要看执行资源是否可用；整体是否更快，还要看分解、调度、通信与同步成本。

## 2. 程序、进程和线程

这三个概念可以按“静态描述 → 资源容器 → 执行路径”理解：

| 概念 | 含义 | 直观理解 |
| --- | --- | --- |
| 程序（program） | 描述如何完成工作的代码和数据文件 | 一份尚未运行的菜谱 |
| 进程（process） | 正在运行的程序实例，持有地址空间和操作系统资源 | 一间独立厨房，拥有自己的工作区和器具 |
| 线程（thread） | 进程中的一条指令执行路径 | 厨房里负责具体工作的人员 |

同一个程序可以启动多个进程；一个进程至少有一个线程，也可以创建多个线程。处理器执行的是线程中的指令，操作系统把进程作为资源与隔离的组织边界。

## 3. 进程：运行程序的资源与隔离边界

进程是操作系统管理运行程序的基本容器。它通常包含：

- **虚拟地址空间**：进程能使用的一组虚拟内存地址，包含程序代码、全局数据、堆和线程栈等区域。
- **程序与运行状态**：可执行代码、当前运行的线程、进程标识符等。
- **操作系统资源引用**：打开的文件、网络连接、设备或其他系统对象。
- **安全与环境信息**：运行身份、权限和环境变量等。

操作系统使用虚拟内存为进程建立彼此分开的地址空间。一个进程中的普通内存写入不会直接改写另一个进程的私有地址空间，因而进程之间形成了较强的故障隔离。进程也可以通过共享内存等机制有意共享特定区域。[Microsoft 对进程与线程的说明](https://learn.microsoft.com/en-us/windows/desktop/ProcThread/about-processes-and-threads)

可以把进程看作一组由操作系统维护的资源和执行上下文。程序启动时，操作系统创建进程、准备地址空间与所需资源，再启动至少一个线程执行程序入口。此后，进程可以继续创建子线程，也可以创建其他进程。

### 3.1 进程内部有哪些东西

进程的核心组成包括：

1. **代码与数据**：程序指令、全局变量和运行时数据。
2. **堆（heap）**：运行时按需申请和释放的动态内存。
3. **线程栈（stack）**：每条线程调用函数时使用的局部变量、返回位置等信息。
4. **进程资源表**：打开文件、套接字和系统对象的引用。
5. **执行线程**：至少一条线程保存当前指令位置、寄存器等 CPU 执行状态。

操作系统内核会维护相应的进程管理信息，用来识别进程、记录资源并管理其生命周期。进程中的线程共用该进程的地址空间和大部分进程级资源；每条线程则保留自己的寄存器状态、栈和线程局部数据。

## 4. 进程状态：操作系统如何描述一项工作

进程执行期间会在不同状态之间切换。入门时常用五状态模型理解：

| 状态 | 含义 | 例子 |
| --- | --- | --- |
| 新建（New） | 操作系统正在创建进程和准备资源 | 刚启动服务进程 |
| 就绪（Ready） | 进程已有执行条件，等待处理器时间 | 线程可运行，但 CPU 正忙 |
| 运行（Running） | 其中一条线程正在处理器上执行 | 正在计算请求数据 |
| 阻塞 / 等待（Blocked / Waiting） | 等待某个事件或资源，暂时无法继续 | 等待磁盘、网络响应或锁 |
| 终止（Terminated） | 程序执行结束，操作系统正在回收或已回收资源 | 请求处理 worker 退出 |

常见状态转换：

- 新建完成后进入就绪；
- 调度器从就绪任务中选出一条线程，让它进入运行；
- 时间片用尽或更高优先级任务到来时，运行线程回到就绪；
- 运行线程发起等待操作时进入阻塞；
- 等待的事件完成后，线程回到就绪；
- 程序完成或被终止后进入终止状态。

这个状态图帮助理解“任务为何没有运行”：它可能正在等 CPU（就绪），也可能正在等 I/O 或其他条件（阻塞）。实际操作系统还会使用更细的状态名称；在多线程进程中，状态主要描述各条线程是否可运行，进程还持有整个程序的资源和生命周期信息。

## 5. 多进程：用隔离的运行实例承载任务

多进程是启动多个独立的进程，让它们分别执行任务。操作系统为每个进程管理自己的地址空间和资源视图。

### 多进程适合的场景

- **任务需要较强隔离**：一个 worker 退出或发生错误时，其他进程可以继续运行。
- **任务需要独立扩展**：可以分别启动、停止和限制不同工作进程。
- **工作主要消耗 CPU**：多个进程可以由操作系统调度到不同 CPU 核上并行执行。
- **需要运行不同组件或权限边界**：每个进程可以按职责运行并持有各自资源。

### 进程间怎样交换信息

进程有各自的地址空间，因此共享数据需要操作系统提供通信方式。常见的进程间通信（IPC）包括：

- 管道和命名管道；
- 本地或网络套接字；
- 消息队列；
- 显式建立的共享内存。

每种方式在拷贝成本、延迟、容量、生命周期和故障处理方面各有特点。第 5 章会专门展开共享内存与消息传递。

多进程通常比同一进程里的线程需要更多启动和管理资源；进程间通信也需要明确的通道。换来的是更清楚的内存与故障隔离，以及独立的运行生命周期。

## 6. 线程：进程中的执行路径

线程（thread of execution）是在进程资源范围内独立推进的一条指令序列。操作系统可以调度线程；在多核 CPU 上，属于同一进程的不同线程也可以运行在不同核心上。

### 6.1 线程有哪些特征

同一进程中的线程：

- **共享进程资源**：包括虚拟地址空间、代码、全局变量、堆以及大部分打开的资源。
- **有自己的执行状态**：每条线程有自己的程序计数位置、寄存器状态和调用栈。
- **可以直接访问共享对象**：线程之间传递数据通常不必像独立进程那样经过单独的 IPC 通道。
- **需要协调共享写入**：多条线程同时修改同一个共享对象，必须定义访问顺序和同步规则。

Linux 的 POSIX 线程说明列出了线程共享的进程资源，也指出线程各自拥有栈；Microsoft 文档同样把线程描述为进程中可被调度执行的实体。[Linux pthreads(7)](https://man7.org/linux/man-pages/man7/pthreads.7.html) [Microsoft：进程与线程](https://learn.microsoft.com/en-us/windows/desktop/ProcThread/about-processes-and-threads)

共享内存让线程间协作直接，也让错误更容易相互影响。例如，两个线程同时读取一个计数值、各自加一再写回，结果可能只增加一次。锁、原子操作等同步机制用来规定共享数据的访问方式；竞态条件和同步工具将在后续章节深入学习。

### 6.2 线程与进程的取舍

| 比较点 | 多进程 | 多线程 |
| --- | --- | --- |
| 地址空间 | 每个进程有独立地址空间 | 同一进程内线程共享地址空间 |
| 隔离 | 隔离边界清楚，进程之间互不直接改写普通私有内存 | 线程共享对象，错误或不安全写入可影响同一进程中的其他线程 |
| 通信 | 通过 IPC 交换数据，需要管理通信通道 | 可直接访问共享对象，传递数据方便 |
| 创建与管理 | 通常需要更多系统资源 | 通常更轻量，创建和切换成本较低 |
| 常见适用方向 | 强隔离、独立服务、CPU 密集型并行任务 | 共享数据较多、需要并发处理多个 I/O 或协作任务 |

表格中的“通常”反映常见运行时的相对开销；实际成本由操作系统、运行时、语言和工作负载共同决定。选择时先看隔离和共享需求，再看计算类型、通信量和调度成本。

## 7. 线程是怎样实现和调度的

线程需要保存足够的状态，才能在暂停后继续运行。处理器执行一条线程时，CPU 中有它当前的指令位置、寄存器值、栈指针等状态；操作系统或运行时在切换任务时保存这些信息，随后恢复另一条线程的状态。

### 7.1 内核线程

内核线程由操作系统内核识别和管理。内核调度器可以让线程在可用 CPU 核之间运行，并在一个线程等待时调度其他可运行线程。

常见优势：

- 操作系统能统一管理线程优先级、阻塞和调度；
- 多条线程可以同时使用不同 CPU 核；
- 一个线程等待时，其他线程仍能继续推进。

成本来自线程的创建、栈和内核管理状态，以及线程切换时保存和恢复执行状态。线程数量增加会消耗内存，也会带来调度与协调工作。

### 7.2 用户态任务与运行时调度

有些语言运行时会在用户态创建更轻量的执行单元，例如 green threads 或 goroutines，再由运行时把它们安排到一个或多个操作系统线程上执行。这样可以用较低成本管理大量等待 I/O 的任务，运行时也可以根据语言的调度模型进行切换。

理解这类机制时，区分两个层级：

- **内核线程**是操作系统能直接调度到 CPU 上的执行实体；
- **用户态任务**由语言运行时调度，最终仍需运行在操作系统线程上。

从用户态任务到内核线程的映射可以有不同组织方式：许多用户任务复用少量内核线程，或每个用户任务对应一个内核线程，也可以采用两层结合的调度模型。映射方式会影响 CPU 并行度、阻塞行为和调度开销。

### 7.3 线程切换

线程切换时，运行时或操作系统保存当前执行上下文，再恢复下一条线程的上下文。切换让单个核心能够交替推进多个任务；多核系统还可以在同一时刻运行多条线程。

切换和调度需要消耗时间，且共享状态可能引入同步成本。因此，实际系统会平衡线程数量和任务粒度。第 6 章会进一步讨论抢占式调度、时间片和上下文切换。

## 8. 在 Python 服务中理解进程、线程和 asyncio

Python 服务通常会同时出现进程、线程与协程。它们解决的问题层次不同：

| 机制 | 谁负责调度 | 适合的直观任务 |
| --- | --- | --- |
| multiprocessing / 进程池 | 操作系统调度不同进程 | 分隔故障边界，或并行处理 CPU 密集型工作 |
| threading / 线程池 | 操作系统调度线程 | 多个工作共享进程资源，尤其是等待网络或文件 I/O |
| asyncio / 协程 | 事件循环在用户态调度协程 | 大量非阻塞 I/O 请求在等待期间交替推进 |

对于标准 GIL 构建下的 CPython，GIL 限制多个线程同时执行 Python 字节码，因此线程特别适合等待网络、数据库或文件 I/O 的任务；纯 Python 的 CPU 密集型工作通常可以考虑进程池。调用会释放 GIL 的原生数值库时，多线程仍可能让底层计算并行。CPython 从 3.13 起提供可选的 free-threaded 构建，Python 3.14 文档说明这种构建已正式支持，但默认发行版仍不默认关闭 GIL。[Python threading 文档](https://docs.python.org/3.14/library/threading.html) [Python free threading 文档](https://docs.python.org/3.14/howto/free-threading-python.html)

asyncio 协程由事件循环调度，不等同于操作系统线程，也不会因为创建了许多协程就自动把 Python 计算分配到多个 CPU 核。协程适合在非阻塞 I/O 等待期间让其他任务继续运行；需要 CPU 并行时，可以结合线程池、进程池或原生计算库。

### 放到 AI 服务请求中看

一个 API worker 收到多个请求时：

- 多个 **进程 worker** 可以隔离各自的应用状态，并由操作系统分配到不同 CPU 核；
- 进程内的 **线程** 可以共享模型对象或缓存，处理需要并发推进的阻塞操作；
- **asyncio 协程**可以管理大量网络请求等待、数据库访问等非阻塞 I/O；
- GPU kernel 由设备端的大量线程执行，是另一种硬件并行模型，和 CPU 的 OS 线程概念不同。

设计服务时，应先说清“哪种执行实体承载哪类任务”，再决定进程数、线程数、异步任务数和 GPU 调度方式。

## 9. 本章记忆卡

- **程序**是代码和数据的静态描述；**进程**是运行中的程序实例；**线程**是进程中的执行路径。
- 进程通常拥有独立虚拟地址空间和操作系统资源，并至少包含一条线程。
- 线程共享进程的大部分资源，但保留各自的寄存器状态、栈和线程局部数据。
- 操作系统调度可运行线程；等待 I/O 或资源的线程会暂时阻塞。
- 多进程以 IPC 进行显式通信，适合隔离与独立运行；多线程共享地址空间，适合低开销协作。
- 并发不自动等于并行；真正同时执行依赖可用的 CPU 核或其他并行执行资源。
- Python 中的进程、线程与 asyncio 协程由不同层次的调度机制管理，选择时要结合 I/O、计算、共享数据和 GIL 构建类型。

### 面试表达：进程和线程有什么区别，服务端怎样选择？

> 进程是操作系统管理运行程序的资源与隔离边界，通常有独立的虚拟地址空间和资源表；线程是进程中的执行路径，同一进程中的线程共享地址空间和大部分资源，但各自拥有寄存器状态和栈。多进程适合需要隔离、独立扩展或 CPU 密集型并行工作的场景，通信需要 IPC；多线程共享数据方便、开销通常较低，适合 I/O 等待较多或需要共享进程内对象的场景，但要同步共享状态。在 Python 服务中，我还会把 asyncio 协程单独看作由事件循环调度的用户态任务，并结合 GIL、I/O 类型、计算负载和部署方式决定具体模型。
