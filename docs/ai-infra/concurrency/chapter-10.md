# 并发基础：第 10 章 非阻塞 I/O

前几章讨论了任务如何拆分、由谁执行，以及共享状态如何同步。本章转向网络服务：客户端请求到达后，服务器要等网络、读取数据、处理请求并返回结果。连接很多、I/O 等待时间很长时，怎样让其他请求继续推进？

主线是：**客户端—服务器 → Socket → 阻塞式服务器 → C10K 问题 → 非阻塞 I/O**。

## 1. 客户端、服务器与 Socket

分布式系统由通过网络交换消息的独立计算机组成。典型的客户端—服务器模型中，客户端发起请求，服务器监听并接收连接、读取请求、执行处理，再把响应发回去。

**Socket（套接字）**是操作系统提供的通信端点。服务器在地址和端口上监听，客户端连接后，双方通过 Socket 发送和接收字节。一个请求大致经过：

~~~text
客户端发送请求 → 网络传输 → 服务器读取请求
→ 执行业务逻辑（可能再访问数据库或模型服务）
→ 服务器写回响应 → 客户端接收
~~~

网络延迟、对端处理速度和下游服务响应时间都不可由当前程序直接控制。服务器常会花很多时间等待，而不是持续执行 CPU 计算。

## 2. 阻塞式 I/O：未完成时当前线程等待

在**阻塞式 I/O（blocking I/O）**中，程序调用读取或接收操作后，如果数据还没准备好，调用线程就会等待，直到操作完成或发生错误。

最简单的服务器按顺序执行：

~~~text
accept 新连接 → 读取请求 → 处理请求 → 写响应 → accept 下一个连接
~~~

代码流程直接，但一次慢请求可能挡住后续请求。一个常用改进是由监听线程持续接收连接，再把每个连接交给工作线程处理。某个线程等待网络时，其他线程可以工作。

**线程池**能限制线程数量、避免每个请求都无限创建线程，但工作线程阻塞等待时仍被占用；线程也要消耗栈空间和调度成本。连接数增长到很大时，线程过多会引入内存占用、上下文切换和管理开销。

## 3. C10K 问题：连接数不等于同时计算的任务数

**C10K 问题**用“一台服务器同时管理约一万个客户端连接”来概括高并发连接管理的挑战。它不是固定的性能门槛，也不单由 CPU 算力决定。关键是大量连接很多时候都在等待网络数据；如果每条空闲连接都长期占一个线程，线程管理成本会很高。

应当区分：

- **连接数量**：当前建立了多少连接；
- **活跃工作量**：此刻有多少请求需要 CPU 或 I/O 处理；
- **等待时间**：请求有多少时间处于等待读写或下游响应状态。

若很多客户端处于空闲，服务器不必为每条连接持续占用一个线程。可以集中等待多个 Socket 的状态，只在连接可读或可写时处理。

## 4. 非阻塞 I/O：暂时无法完成时尽快返回

**非阻塞 I/O（nonblocking I/O）**让读、写、接收等调用在当前无法完成时尽快返回，而不让调用线程一直睡在这次操作上。程序可以先处理其他连接，稍后再回来。

非阻塞读取可能：

1. 读取到一些已到达的数据；
2. 立即返回“当前没有数据可读”；
3. 返回连接关闭或错误等状态。

所以非阻塞不等于操作已经完成，也不等于程序永远不等待。程序还需要知道何时再试，这就是下一章 I/O 多路复用和事件循环要解决的问题。

TCP 是字节流，应用还要管理数据边界和缓冲区：一次读取可能只得到半个请求，一次写入也可能只发出一部分响应。剩余数据需要保存，等下一次可读/可写时继续处理。非阻塞模型让调用快速返回，但连接状态机与缓冲管理更重要。

## 5. 三种模型如何取舍

| 模型 | 做法 | 优点 | 主要成本 |
|---|---|---|---|
| 阻塞单线程 | 一次处理一个请求 | 流程简单 | 慢 I/O 会挡住其他请求 |
| 阻塞 I/O 加线程池 | 工作线程各自等待 I/O | 顺序代码好理解，线程数可控 | 线程占用、调度、切换和锁 |
| 非阻塞 I/O 加事件通知 | 少量线程管理很多 Socket | 空闲连接不必各占一线程 | 连接状态、事件和错误处理更复杂 |

连接不多、业务简单时，阻塞 I/O 或线程池便于维护；大量连接大部分时间在等 I/O 时，事件驱动方式能减少线程资源开销。CPU 密集型任务仍需安排计算资源，非阻塞 Socket 不会自动加速计算。

## 6. 本章小结

- Socket 是应用使用操作系统网络能力的通信端点。
- 阻塞 I/O 未就绪时会占住当前线程，代码直观但并发连接很多时资源成本增加。
- C10K 问题关注大量连接的管理效率；连接数不等于同时需要 CPU 处理的任务数。
- 非阻塞 I/O 在当前无法继续时快速返回，应用保存连接状态，并借助事件通知判断何时再处理。
- TCP 可能部分读写，程序需要维护消息边界、缓冲区与连接状态。
- 下一章讲事件循环怎样等待很多连接的就绪状态并分派处理。

### 面试表达：高并发网络服务为什么使用非阻塞 I/O？

> 网络服务很多时间都在等客户端数据或下游服务。如果每个连接都由一个线程阻塞等待，连接数很大时线程栈、调度和上下文切换成本会增加。非阻塞 I/O 让操作暂时无法推进时尽快返回，再通过 I/O 多路复用等待多个连接就绪；事件循环收到通知后处理对应连接。它主要改善 I/O 密集、连接数大的场景，CPU 密集工作仍需另外安排计算资源。
